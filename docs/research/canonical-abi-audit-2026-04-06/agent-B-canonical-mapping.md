## Executive Summary

1. **Multiple parallel implementations exist.** Wazero has at least four independent lift/lower code paths operating on two different type systems. The authoritative runtime paths (used by guest→host and host→guest calls) are in `internal/component/component_linker.go` and `internal/component/instance.go`. A separate cleaner implementation lives in `internal/component/abi/` but is **not referenced by any non-test runtime code** — it is dead code for the runtime and only exercised by tests in `internal/component/conformance/`. A fourth path exists in `internal/component/canon_lower.go` for some host-function wiring.
2. **No single `canon_lift` or `canon_lower` function exists.** The spec functions `canon_lift` and `canon_lower` are implicit in `ExportedFunc.Call` (instance.go:133) and `createCanonLowerFunc` (component_linker.go:2430). This makes side-by-side comparison against the spec text difficult and is partially responsible for drift between paths.
3. **Several canonical ABI correctness gaps exist in the runtime paths** — not in `abi/`, but in the paths that are actually wired into calls. Notable: wrong `join` semantics in `flattenVariantType` (component_linker.go:3747-3775); a hard-coded 4-byte discriminant width for options/results/variants in `writeResultsToMemory` (component_linker.go:3260-3315) and `liftFieldFromMemory` (instance.go:1335-1402); a placeholder `0` discriminant for variants in `writeResultsToMemory` (component_linker.go:3292); an f32 cast from i32 without bit-reinterpretation in `liftFromStack` (component_linker.go:2569); and a retptr flat-lift path for records that assumes one core-result per field (instance.go:807-814).
4. **Resource handle ABI differs from spec.** Wazero's `ResourceTable` uses a 64-bit handle with a generation counter in the upper 32 bits (`resource_table.go:36-49`). The canonical ABI passes `i32` indices only. Wazero works around this by zero-generation casts at the call sites (`Handle(handleIdx)`), which functions correctly only so long as slots are never freed and reused.
5. **`abi/` package is the most spec-compliant implementation** — it correctly handles variant join/coercion, string encoding options, Latin-1+UTF16, NaN canonicalization, and despecialization of option/result/tuple/enum via explicit type handling. It is also the most heavily tested in `internal/component/conformance/`. It just is not used by the runtime.

## Notable Bugs and Deviations Found (Runtime Paths Only)

This list is the result of my direct reading of the runtime paths, independent of any other agent's analysis.

### Critical (wrong output from runtime paths)

1. **Wrong variant flat `join` semantics** (`component_linker.go:3779-3797`, `3747-3775`). `isWiderValueType` orders `i32:1 < f32:2 < i64:3 < f64:4` and picks the wider for each slot. Spec says `join(i32,f32) = i32`, but wazero produces `f32`. This causes guest exports with variant parameters to see the wrong flat core signature when calculated via `flattenValType` / `flattenVariantType`. The correct `join` is implemented in `abi/flatten.go:217-226` but that path is unused at runtime.
2. **Wrong discriminant size in `writeResultsToMemory` for Option/Result/Variant** (`component_linker.go:3260-3315`). The code writes a 1-byte discriminant and then advances offset by 4 unconditionally. For Option/Result, spec says disc type is u8 (1 byte) and payload offset is `alignTo(1, payloadAlign)`, which is 1 when payloadAlign=1. For Variant the disc may be 1, 2, or 4 bytes. This hard-coded 4-byte advance produces incorrect memory layouts whenever the result of a host canon-lower is a composite returned via retptr.
3. **Placeholder variant discriminant** (`component_linker.go:3292`). `memory.WriteUint32Le(offset, 0) // Placeholder discriminant`. The code knows it doesn't have type info to compute the real discriminant index and writes zero. Any variant returned from a host function via the component-linker canon-lower path will always be decoded as case 0.
4. **Wrong f32/f64 cast in `liftFromStack`** (`component_linker.go:2569,2571`). `return ValF32(float32(stack[0])), 1` and `return ValF64(float64(stack[0])), 1`. These convert a uint64 bit pattern to float32/float64 via Go's numeric conversion, not via `math.Float32frombits`/`math.Float64frombits`. For any non-zero bit pattern this produces a completely different value. The correct form is used elsewhere in the file for `lowerToStack` F32/F64 (line 3108: `stack[0] = uint64(val.U32()) // F32 bits`). This is specifically the `liftFromStack` path used by `createCanonLowerFunc` when a component-internal canon lower invokes a host function with a float parameter or result.
5. **Option discriminant size in `liftFieldFromMemory`** (`instance.go:1355-1365`). Reads `ReadUint32Le(offset)` for the option discriminant — 4 bytes. Spec says option has 2 cases, so its discriminant type is u8 (1 byte). The code also computes `payloadOffset := offset + 4`, not `offset + alignTo(1, payloadAlign)`. Nested options inside records/lists will be misaligned.
6. **Enum/Flags size in `liftFieldFromMemory`** (`instance.go:1335-1354`). Always reads 4 bytes regardless of case count or flag count. Spec-defined storage is 1/2/4 depending on counts. Nested enums/flags inside composites are misread.
7. **Record flat lift assumption** (`instance.go:807-814`). `len(coreResults) >= len(t.Fields)` and then `f.liftResolvedPrimitiveVal(coreResults[i], field.Type)`. This assumes one core value per field, which is only true if every field is a primitive. Records with string, list, or composite fields will read the wrong bytes. Also, `liftResolvedPrimitiveVal` returns `ValS32(int32(coreVal))` as the fallback for non-primitive types, silently producing garbage.
8. **Record field alignment missing in `liftFieldFromMemory`** (`instance.go:1385-1393`). Loops fields with `totalSize += size`, no `align_to`. Correct code must align before each field.
9. **Variant flat lift ignores join coercion** (`instance.go:1084-1113`). Reads `coreResults[1]` directly as the payload without considering the joined-type flat layout. If the variant had a case whose flat type differs from the join, the bits will be misinterpreted.
10. **Lowered variant in runtime paths does not coerce to joined type** (`instance.go:1757-1799`). Lowers the case payload via the case's own type then pads with zero. Contrast `abi/lower.go:69-122` which correctly coerces via `coerceFlatValueForLower`.

### Secondary (spec-valid but worth flagging)

11. **Hardcoded UTF-8 in runtime string lowering/lifting** (`instance.go:1964-1985`, `719-753`; `canon_lower.go:442-473`, `326-336`; `component_linker.go:2574-2583`, `3233-3258`). All these paths ignore canonopt `string-encoding` and treat strings as UTF-8. abi package respects all three encodings. Integrated code paths do not.
12. **Fixed-length list flattening only in abi** (`component_linker.go:3632-3633` uses bare `[i32,i32]`). Runtime cannot represent a fixed-length list's flat form correctly.
13. **`may_leave` not enforced in lightweight resource op exports** (`component_linker.go:2155-2198`). The "simple" `createResourceOpExport` path used for some host modules bypasses `may_leave` checks and destructor routing. The richer `CreateResourceDropFuncWithContext` does enforce them but is not wired into all code paths.
14. **Resource type validation missing in runtime resource ops** (`component_linker.go:2155-2198`). `h.rt is not rt` check (spec line 3632, 3686) is implemented in the `*WithType`/`*WithTrap` resource-table helpers but not used by the simple host export code path.
15. **Generation counter in `Handle`** (`resource_table.go:36-49`). Safety-augmenting extension beyond spec, but creates a latent correctness bug when wazero packs generation into an i32 core value. See "Resource Handle Table Semantics" row above.
16. **`Flags.FlattenCount` returns multiple i32s for >32 flags** (`types/composite.go:331-338`). Spec asserts `0 < n <= 32`. Wazero extends to >32 via multiple i32s. This is a deliberate choice but diverges from the spec's assertion. The extension is inconsistently applied in different paths (e.g. `component_linker.go:3739-3742` correctly emits multiple, `canon_lower.go:528-563` correctly emits multiple, but `instance.go:1675-1687` emits `numWords` i32s and `instance.go:1345-1354`/liftFieldFromMemory always reads only one).
17. **No NaN canonicalization in runtime float lift** (`instance.go:704-706`, `component_linker.go:2569-2570`). abi path canonicalizes. Runtime does not. Spec allows either — see wasmtime `typed.rs:1283-1295`. **Valid**, just different between wazero's own paths.
18. **Variant flat lift in `instance.go:1084-1113` assumes `len(coreResults) >= flatCount`** — where flatCount comes from `Variant.FlattenCount()` which returns `1 + max(case.FlattenCount())`. A variant whose cases have wildly different flat counts might not be consumed correctly.
19. **Unicode scalar validation inconsistent**. `abi.LiftFlat`/`LiftHeap` validate chars. `instance.go:liftPrimitiveVal`, `instance.go:liftFieldFromMemory`, `component_linker.go:liftFromStack`, and `canon_lower.go:liftValFromFlat` do not. Surrogate chars will slip through the runtime paths.

## Open Questions / Spec Ambiguities

1. **`alignment_variant` vs `max_case_alignment`.** Spec line 1892 says `alignment_variant(cases) = max(alignment(discriminant_type(cases)), max_case_alignment(cases))`. Wazero initialises from `DiscriminantSize()` which equals `alignment(discriminant_type)` only because all discriminant types are u8/u16/u32 (where `size == alignment`). Not a bug but worth noting.
2. **`PayloadOffset` computation.** Spec computes payload offset in `load_variant` as `align_to(disc_size, max_case_alignment)` after advancing past the discriminant. Wazero pre-computes it via `Variant.PayloadOffset()` (composite.go:148-158). This produces the same result.
3. **Latin-1+UTF16 alignment always 2.** Spec line 2116-2122 requires 2-byte alignment for latin1+utf16 even when the actual data is Latin-1. `abi/strings.go:98-102` and `230-231` comments explicitly affirm this. Runtime paths don't implement Latin-1+UTF16 at all, so this is only validated in abi.
4. **MAX_STRING_BYTE_LENGTH = 2^31 − 1.** Enforced in `abi/strings.go:14` (`utf16Tag`) and implicitly via Go's string length limits. Not explicitly checked in runtime paths.
5. **`trap_if(0xD800 <= i <= 0xDFFF)` on char lift.** Done only in `abi.isValidUnicodeScalar` (lift.go:824-837) and `isValidUnicodeScalarRune` (lower.go:686-702). Runtime paths accept surrogate values silently.
6. **NaN canonicalization in lifting.** Spec lines 2037-2054 say NaNs MUST be canonicalized when lifting (so there is "only one unique NaN value per floating-point type"). Wasmtime does NOT canonicalize on lift (`typed.rs:1287`: `Ok($float::from_bits(src.$get_float()))`). This suggests the spec's wording is prescriptive but implementations have optimized it away. Wazero's abi path canonicalizes; runtime paths do not. Ambiguity: does "must" in spec 2037-2054 bind implementations?
7. **Resource handle layout.** Spec always says `i32` for handle indices. Does this mean the host must store handles in an i32 table, or only that the ABI passes an i32? Wazero interprets the latter (packs generation into 64-bit `Handle` type internally) but the generation bits don't survive the i32 round-trip. The spec does not address use-after-free directly; wazero's extra safety doesn't function as intended.
8. **Retptr as return value vs parameter.** Spec line 2745-2751 says: in `lift` context, retptr is a single i32 return; in `lower` context, retptr is appended as a parameter. Wazero implements both conventions and auto-detects which the core function expects (instance.go:305-322). Spec line 2726-2731 mentions the caller-allocated-buffer optimization as an exception but does not formalize it. TinyGo and Go target the "retptr as result" pattern despite being on the `lift` side, which is consistent with spec line 2748.
