# WASIP2 Go Plugin Debugging Notes

## 2026-01-20
- Baseline run: `CGO_ENABLED=0 go test ./internal/component/wasip2test -v`  
  - Fails in subtest `multi` within `TestCalculatorPlugins`.  
  - Panic: `runtime error: index out of range [0] with length 0` at `internal/engine/wazevo/module_engine.go:177` called from `moduleEngine.NewFunction`.  
  - Call stack shows failure during component instantiation via `ComponentLinker.Instantiate` for WASI P2 component (Go plugin case).  
  - `-run TestCalculatorGoPlugin` pattern was wrong because only `TestCalculatorPlugins` exists (table-driven).  

- Plugin artifacts (wit via `wasm-tools component wit`):
  - `plugins/multi.wasm` (Go): world imports extensive WASI P2 0.2.6 interfaces (cli env/exit/std streams, io/poll/streams, clocks, filesystem types/preopens, random, terminal-*, etc.) and exports `get-plugin-name`, `evaluate`.
  - `plugins/add.wasm` (Rust): imports WASI P2 0.2.3 set (cli env/exit/std streams, io/streams, clocks wall-clock, filesystem types/preopens) and exports same functions.
  - `plugins/subtract.wasm` (C): no imports; only exports `get-plugin-name`, `evaluate`.
  - Version mismatch: Go plugin depends on 0.2.6 while runtime likely implements 0.2.3; may be relevant if relaxed semver mismatch handling is incomplete.

- Wazevo host-module issues uncovered:
  - Inline host modules generated by `ComponentLinker` compile via `compileHostModule` but lacked entry preambles and `sharedFunctions`, causing nil/empty slices and index panics in `moduleEngine.NewFunction`.
  - Host compiled modules also missed engine parent/offsets; parent was nil leading to crashes in stack tracing.
  - Host module opaque layout stored the module pointer (not instance), so `moduleInstanceFromOpaquePtr` dereferenced garbage during stack handling.
  - Fixes applied: compile entry preambles for host modules; set parent/offsets and sharedFunctions; change host opaque to store module instance pointer (and adjust helpers/tests); add nil guard in `moduleInstanceFromOpaquePtr`; defensive lookup for compiled modules.

- Current state after fixes:
  - Instantiation no longer panics; but `get-plugin-name` in Go plugin still traps with `wasm error: invalid table access` inside Go runtime (`runtime.write` -> `get_plugin_name`).
  - Table in Go core module (`unbundled-module0.wasm`) has initial size 5795 funcref; adapter module (`unbundled-module1.wasm`) bridges WASI P2 0.2.6 to P1. Trap likely wazevo/table handling with Go-generated WASM, not yet root-caused.
